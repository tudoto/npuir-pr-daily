AscendNPU-IR Pass Pipeline 总览（A3 / A5）

编译 Pass 执行流程与各阶段说明

← 返回首页

基线：4a26b5f94（分支 fix/ave-pge-normalize-all，整理日期 2026-08-13）。本文按 bishengir-compile 的普通 HIR 编译路径整理；Triton-only、SIMD+SIMT 拆分、Torch 前端和调试注入等旁路放在"条件分支"中。Canonicalize、CSE 等清理 pass 在真实 pipeline 中会多次运行，顺序表保留其关键出现位置，说明表只解释一次。

1. 总体流程

A3（Ascend 910B，mem-based）

CanonicalizeModule → AppendDeviceSpec → HFusion 前端归一化 → 融合与自动调度 → HFusionToHIVM → HIVM 张量优化 → OneShotBufferize → HIVM 内存规划与同步 → ConvertHIVMToStandard → 后端

A5（Ascend 950，RegBase）

AppendDeviceSpec → CanonicalizeModule → HFusion 前端归一化 → 融合与自动调度 → RegBase 向量化 → HFusionToHIVM → HIVM 张量优化 → OneShotBufferize → RegBase 内存规划与同步 → Vector/ArithToHIVMAVE → AVE 优化 → HIVMAVEToAVEIntrin → LLVM/后端

2. A3 Pipeline（按执行顺序）

2.1 顶层与 HFusion

  1. CanonicalizeModule：清理模块级结构并统一可折叠写法。它为后续设备属性和 dialect 转换准备稳定输入。该 pass 只做规范化，不决定硬件调度。
  2. AppendDeviceSpec：把目标芯片、AIC/AIV 数量和后端版本写入模块。后续 pass 通过这些属性选择 A3 规则。它是目标相关决策的统一信息源。
  3. EraseSymbol（默认）：移除未启用符号分析时残留的 symbol 信息。这样后续 shape 与融合分析不会依赖无效符号。启用 symbol analysis 时跳过。
  4. ArithToHFusion、MathToHFusion、LinalgToHFusion、TensorToHFusion：依次把通用算术、数学、Linalg 和 Tensor 操作转换到 HFusion。转换后计算语义集中到适合融合和调度的 dialect。ArithToHFusion 会在清理后再跑一次以接住新暴露的算术操作。
  5. CanonicalizeTensorReshape、CSE、ExtendedCanonicalizer、NormalizeTensorOps：折叠 reshape、公共子表达式和冗余 tensor 结构。它们会在 HFusion 多个阶段反复执行。作用是维持 IR 简洁并为模式匹配创造稳定形态。
  6. ConvertGenericToNamedOp：识别可表达为具名算子的 generic 计算。具名形式包含更明确的计算语义，更利于后续分解和调度。无法识别的 generic op 保持原样。
  7. LegalizeBF16：把不被后续流程直接接受的 BF16 用法改写成合法形式。它处理类型转换和相关运算的边界情况。目标是让后续 pass 不必重复处理 BF16 特例。
  8. Decompose(NO_CONSTRAINT)：拆解 HFusion 聚合操作和复杂算子。它把高层语义变成较小、可调度的基本操作。此阶段不施加后续布局阶段的特定约束。
  9. HFusionNormalizeSliceOps、GenericUnroller、HFusionNormalizeOps：统一 slice 表达、展开适合静态展开的 generic 结构，并规范化数学运算。它们减少同一语义的多种 IR 写法。高精度和快速除法选项会影响数学改写策略。
  10. LegalizeBool、SimplifyOps、HFusionInlineBrc：合法化布尔表达式、简化操作并内联广播计算。内联后再次 Normalize，以统一新形成的标量—向量运算。该组主要降低后续融合和调度的分析复杂度。
  11. BubbleUpExtractSlice、LinalgFoldUnitExtentDims、ComposeMultiReduce、PropagateReshape：把切片向上移动、折叠长度为 1 的维度、组合多重归约并传播 reshape。它们为 flatten 创建规整的数据流。动态形状场景下会尽量保留必要的维度关系。
  12. FoldTensorEmpty、FlattenOps(Tidy)、CacheIOForReturnArg：清理空 tensor，把算子整理为较扁平的形态，并缓存返回参数相关 I/O。Flatten 让自动调度面对更统一的维度结构。缓存步骤避免输出路径被后续变换重复构造。
  13. FoldSymbolicDim、InferFuncFusionKind、HFusionOpFusion：折叠可确定的符号维，判断函数属于哪类融合，再执行算子融合。融合会减少中间结果和访存，同时受水平融合上限约束。结果可能形成一个或多个 kernel 候选。
  14. OutlineSingleOp、UnfoldSymbolicDim、DropSymbols、EliminateDuplicateFuncs：把未融合的单算子也整理成独立 kernel，恢复需要的符号维表达，并清掉编译期符号。最后合并完全重复的函数。该组完成 kernel 边界定型。
  15. DowngradeFP64CstOp、TrickleConcatDown、BubblePadUp、NormalizeLastDimUnalignedTensorOp：降低不必要的 FP64 常量精度，调整 concat/pad 位置，并规范化末维不对齐 tensor。它们修整 outlined kernel 的数据布局。目标是让自动调度看到硬件可实现的形态。
  16. Decompose(AFTER_HFUSION_FLATTEN)、HFusionAutoSchedule、DecomposeMulti：先拆解 flatten 后仍过于复杂的操作，再进行分块、核数和数据搬运调度。调度产生的复合操作随后被继续拆开。HFusionAutoSchedule 是 HFusion 阶段决定性能结构的核心 pass。
  17. ConstantizeTilingData、PackTilingData：把可静态确定的 tiling 参数常量化并打包。运行时只需读取紧凑的 tiling 数据结构。它也会生成或维护相关的 tiling 辅助函数。
  18. ArithToAffine、SCFForLoopCanonicalization：把适合的整数索引计算转换为 affine，并简化 scf.for。这会暴露常量边界和可折叠循环。它们主要服务于后续低层优化，而不改变算法语义。
  19. WrapHostFunc：为设备 kernel 构造宿主侧包装函数。包装层负责整理调用参数和 tiling 数据。多 kernel 模式下其行为受配置控制。
  20. AddFFTSAddr、HoistTensorEmpty、Decompose：补充 FFTS 所需地址信息，把可提升的 tensor.empty 移到更合适位置，并完成 HFusion 尾部拆解。它们是进入 HIVM 前的最后清理。A3 是否真正使用 FFTS 取决于目标能力与选项。

2.2 A3：转换到 HIVM 与张量级优化

  1. HFusionToHIVM：把 HFusion 核心计算、搬运和矩阵操作转换为 HIVM。普通 HIR 路径使用 CoreOp 形式表达矩阵计算。此后 IR 开始显式体现 NPU 内存层级和核类型。
  2. TensorToHIVM、ConvertToHIVMOp、PropagateReshape：转换剩余 tensor/通用操作，并传播转换中插入的 reshape。它们保证主要计算都进入 HIVM 可处理集合。A3 在此保留并整理 mem-based 表达。
  3. InitEntryKernel：在 kernel 入口插入必要的初始化语义。典型用途是初始化向量 mask 等硬件状态。这样各 kernel 不依赖调用前的隐式状态。
  4. RemoveRedundantLoopInit、NormalizeMatmul、NormalizeConvOps、NormalizeBitwiseSelect：删除多余循环初值，并统一矩阵乘、卷积和位选择操作。规范化后，fixpipe、布局和内存分析可以匹配固定模式。该组不会决定最终地址。
  5. InsertFixpipe、InlineFixpipe：为矩阵结果补充 fixpipe 路径，并把可融合的量化、缩放或格式处理并入现有 fixpipe。它减少额外搬运和独立向量计算。pipeline 前后各运行一次，以覆盖 tiling 新产生的模式。
  6. InsertLoadStoreForMixCV、InsertLoadStoreForScalar：在 Cube 与 Vector 跨核交互处显式插入 load/store。标量跨核传递也被转成清晰的内存通信。非 MixedCV 输入上大部分模式会自然无操作。
  7. InsertConvertLayout、PropagateConvertLayout、CombineOptimizedConvertLayout、ConvertLayoutToTranspose（条件）：插入并传播布局转换，再把可合并的转换折叠进 load 或 fixpipe。剩余转换被降成 transpose。A3 默认关闭 layout optimization，显式启用时才进入该组。
  8. TileBatchMMIntoLoop、InsertNZ2NDForDebug：把 batch matmul 分块为循环，并为 A3 调试路径补充 NZ 到 ND 的转换。这样每次矩阵计算规模更接近硬件基本块。调试转换也让中间结果更易观察。
  9. InsertWorkSpaceForMixCV、BindWorkSpaceArg：为跨核通信创建全局 workspace，并把它绑定到函数参数。workspace 的具体地址随后由 PlanMemory 统一规划。禁用自动 CV workspace 管理时跳过。
  10. InferFuncCoreType：判断函数运行在 AIC、AIV 还是 MIX 模式。这个标记决定后续拆核、同步和内存范围。错误的核类型会直接导致通信或调度不成立。
  11. MarkMultiBuffer：标记适合双缓冲或多缓冲的 workspace/local buffer。它只建立候选和缓冲深度信息，尚不改写最终槽位选择。后续 PlanMemory、同步和 EnableMultiBuffer 会共同完成落地。
  12. InlineOTFBroadcast、CVPipelining（条件）：内联 on-the-fly broadcast，并在 MixedCV 场景把 Cube/Vector 工作重排成软件流水。流水可重叠计算与搬运，减少核间等待。关闭 CV pipeline 时只执行广播清理。
  13. PartitionAndBindSubBlock、TileCubeVectorLoop（条件）：按配置划分并绑定 sub-block，或分别调整 Cube/Vector 循环 tile。它们用于负载均衡和硬件子块利用。默认关闭或参数为 1 时不改写。
  14. AutoInferBufferSize、ConstantizeBufferSize、SetBufferSize、PlanMemory(GLOBAL)：推导、常量化并写回 buffer 大小，然后规划全局 workspace 地址。该阶段决定跨函数/跨核共享区的布局。它不负责最终 UB/L1 局部地址。
  15. CrossCoreGSS / InjectBlockSync：分析 AIC/AIV 之间的数据依赖并插入块级同步。Graph Sync Solver 路径尽量只保留必要同步，保守模式则注入更强屏障。具体选择由同步相关选项决定。
  16. MarkTightlyCoupledBuffer、HoistTightlyCoupledAlloc：给紧耦合跨核 buffer 分配一致标识，并把逃逸出内部区域的 alloc 提升到共同锚点。这样 AIC/AIV 克隆能共享相同的缓冲和多缓冲语义。它们必须在 SplitMixKernel 前运行。
  17. SplitMixKernel、InlineScope：把 MIX 函数拆成 AIC 与 AIV 函数，并内联中间 scope。拆分依据前面推导的核类型和通信标记。拆分后两侧通过 workspace 与同步关联。
  18. TileAndBindSubBlock：把适合的循环切分并绑定到硬件 sub-block。A3 上是否真正切 tile 由 enableAutoBindSubBlock 控制。即使不开启，也会保持结构合法并执行必要整理。
  19. LoopInvariantCodeMotion、LoopInvariantSubsetHoisting（条件）：把循环不变量和不变切片移到循环外。它们减少重复计算与重复地址构造。仅在 code motion 选项启用时执行。
  20. CloneTensorEmpty、HIVMInlineOTFLoadStore：复制被错误共享的 tensor.empty 锚点，并内联可即时完成的 load/store。前者避免 CSE 破坏 destination-style 语义，后者减少无意义中间层。它们完成 bufferization 前清理。

2.3 A3：Bufferization、内存与最终 Lowering

  1. ExposeMemrefWriteToTensor、TensorCopyInsertion、OneShotBufferize：先暴露隐藏在 tensor 后的 memref 写，再分析冲突并插入必要 copy，最后把 tensor SSA 转成 memref。函数边界也一起 bufferize，未知操作被保守保留。该组是张量 IR 转内存 IR 的分界点。
  2. DropEquivalentBufferResults、ConvertToHIVMOp：删除与输入 buffer 等价的冗余返回值，并把 bufferization 生成的 memref.copy 等重新转成 HIVM 操作。清理会执行多轮以暴露更多等价关系。结果是更明确的原地读写 IR。
  3. LiftZeroRank、MapForToForall、HIVMMapForallToBlocks：处理零维值，并把可并行循环映射成 forall 和硬件 block。它们建立逻辑并行与物理执行块的联系。后续 lower-to-loops 会把结构进一步具体化。
  4. HIVMDecomposeOp：分解仍然过于高层的 HIVM 操作。它在 memscope 推导前后及最终 lowering 后多次运行，每次处理当时才具备条件的模式。重复运行是阶段化 lowering 的设计，不是冗余。
  5. SyncBlockHoisting、BindSyncBlockLockArg、InsertInferSyncBlockLockNumAndInitFunc、SyncBlockLockLowering：提升 sync-block，绑定锁参数，生成锁数量/初始化辅助函数，并降低锁操作。该组为跨 block 锁同步建立完整生命周期。最终还会补 free 路径。
  6. NonContiguousReshapeToCopy、InferHIVMMemScope：把非连续 reshape 显式化为 copy，再推导 GM、L1、UB 等内存空间。先转 copy 可避免在 AIC 函数里误产生 UB 分配。新 buffer 产生后 memscope 会再次推导。
  7. HIVMRecognizeDeinterleaveOp、HIVMRecognizeDisContinuousStore：识别非连续访问并改写为 deinterleave 或离散 store。专用操作能更准确映射硬件搬运模式。A5 RegBase 会跳过 deinterleave 识别，而 A3 执行。
  8. HIVMAggregatedDecomposeOp：按多个 phase 分批拆解聚合操作。它分别等待 stride alignment、broadcast 识别、data layout 和 flatten 等信息成熟。阶段化处理避免过早展开导致优化机会丢失。
  9. AlignAllocSize、MarkStrideAlign、FoldAllocReshape、EnableStrideAlign：对齐分配大小，标记合适的 stride 对齐，折叠 alloc+reshape，并真正启用对齐布局。自动 stride alignment 受选项控制。该组确保 DMA 和向量访问满足硬件对齐要求。
  10. InferHIVMDataLayout、RemoveHIVMDataLayoutAnnotation：推导 ND/NZ 等数据布局，并在布局被消费后移除临时标记。推导结果决定 copy 是否能变成 ND2NZ 等专用操作。清理标记防止后续错误重复使用旧结论。
  11. FlattenOps、ReduceRankSubview、LiftLowestStride、AllocExtraBuffer：压平内存操作，降低 subview 秩，提升最低层 stride，并为需要临时空间的操作分配额外 buffer。它们把复杂 memref 视图变成后端更容易处理的地址计算。新增 buffer 随后重新推导 memscope。
  12. InlineLoadCopy：把可以直接合并的 load-copy 路径内联。这样减少一次中间 buffer 或多余 copy。它在最终局部内存规划前执行。
  13. MarkMultiBuffer、PlanMemory(LOCAL)：再次标记局部多缓冲候选，并为 UB/L1 等本地 buffer 分配最终地址。此时 IR 已经完成主要分解，所以内存生命周期更准确。地址复用和容量检查也在这里完成。
  14. HIVMLowerToLoops：把结构化 HIVM 操作降低成显式循环和更基础的操作。它将 tile、搬运和计算的迭代空间具体化。此后后端不再需要理解多数高层 HIVM 结构。
  15. CreatePreload（条件）：为 skew CV pipeline 构造 preload、稳态和 drain 控制流。它使下一批数据搬运能与当前批计算重叠。仅在 preload 模式启用。
  16. GraphSyncSolver / InjectSync：在单核内部分析流水和内存依赖，插入 event/flag 同步。GSS 尝试最小化同步，InjectSync 提供保守替代。它与前面的跨核同步解决不同层次的问题。
  17. LowerMemRefExt、AddFFTSToSyncBlockSetOp：降低扩展 memref 操作，并为需要的 sync-block set 补充 FFTS 信息。前者消除后端不认识的扩展抽象。后者只在相关目标/模式上产生实际效果。
  18. EnableMultiBuffer、LowerMultiBufferCounter：把多缓冲标记真正改写为槽位轮转和地址选择，并降低轮转计数器。至此双缓冲不再只是属性，而成为显式控制流。它依赖 PlanMemory 和同步已经完成。
  19. NormalizeArith、LiftArithIndexCast：规范化低层算术并提升可消除的 index cast。它们简化最终地址和循环计算。A3 pipeline 在尾部直接执行这两项清理。
  20. InlineScope(force)、EnableHIVMCompatiblePrint、AnnotationLowering、AllocToAlloca：强制内联剩余 scope，转换调试打印，降低 annotation，并把非 GM alloc 改为栈式 alloca。该组清除编译器内部结构。输出已接近标准/LLVM 可接受形式。
  21. InsertInitAndFinishForDebug、MarkDisableLoad、MarkSyncBlockLockWithSubblock、InsertFreeLockVarBeforeReturn：补齐调试初始化/结束逻辑，标记可禁用 load，并完成锁与 sub-block 的关联和释放。它们确保特殊运行模式的资源生命周期完整。普通模式下部分 pass 可能无改写。
  22. ConvertHIVMToStandard、FixCallUnknownLoc：把剩余 HIVM 操作转换为标准低层 dialect，并为缺失位置的 call 补上合法 location。后者避免 LLVM debug-info verifier 报错。A3 的 in-tree pipeline 至此完成，随后交给后端。

3. A5 Pipeline（RegBase）

A5 的 HFusion 融合与调度主干和 A3 基本一致，但增加 UpliftWhileToFor、LegalizeFP8、RegBase 向量化以及 AVE lowering。下面只列 A5 新增或行为明显不同的 pass；未列出的共同 pass 按第 2 节相同含义理解。

3.1 A5 HFusion 与向量化

  1. UpliftWhileToFor：识别具有标准计数循环形态的 scf.while 并改写成 scf.for。for 结构更容易做 tiling、向量化和循环分析。无法证明等价的 while 会保持不变。
  2. LegalizeBool(clamp)、LegalizeScalar、HFusionGeneralize、HFusionFoldUnitDims：先规范化布尔与标量语义，再把需要的具名操作 generalize 并折叠单位维。该组主要服务 Triton/RegBase 输入的统一。它降低不同前端形态对向量化器的影响。
  3. LegalizeFP8：把 FP8 类型和相关运算改写成 A5 pipeline 可处理的合法形式。它处理转换、常量和算术语义的细节。A3 当前 HFusion 主线没有这一独立步骤。
  4. FoldExtractInsertPair、SinkOpToConsumerInLoop：删除成对抵消的 extract/insert，并把操作下沉到循环内消费者附近。这样可缩短临时值生命周期并减少中间 tensor。它们在向量融合前整理 VF 候选。
  5. VFFusion（默认启用）：把多个向量函数融合成更大的 VF。融合减少函数边界和中间 UB 搬运，但会受模式和 UB 预算约束。UB-aware 模式会阻止融合结果超过本地内存容量。
  6. FuseTransposeIntoLoad、PreVectorizationFusion、PrepareI1Nx1ForVectorization：把 transpose 融入 load，融合适合一起向量化的 elementwise 操作，并准备特殊 i1/N×1 形态。它们减少显式布局操作和向量化障碍。最大融合规模由选项控制。
  7. HFusionAutoVectorizeV2 / HFusionAutoVectorize：选择新版或旧版策略，把标量/张量循环转换成向量函数。V2 支持更复杂的融合和多消费者策略。两者只会选择其一。
  8. OutlineVectorFunction、AutoVectorizeVerifier：V2 路径把向量循环 outline 为 VF，随后验证向量化结果满足约束。验证失败会尽早暴露非法形态。旧版也会经过统一 verifier。
  9. TreeReduceV2、HFusionToVector、RemoveMaskFromUnalignedReductionLoop、LowerVectorMask：优化树形归约，把 HFusion 向量操作转成 MLIR Vector，并降低 mask。对不对齐归约，会先移除不适合保留的 mask 结构。结果成为 HIVMAVE 可以接收的标准向量 IR。
  10. PullSliceIntoVectorFunction、SimplifyVFArgs、LoopInvariantSubsetHoisting、LoopInvariantPromotion：把 slice 拉进 VF，简化 VF 参数，并提升循环不变子集和值。它们减少调用参数和循环内开销。Promotion 是否运行由配置控制。
  11. RemoveRedundantWriteAndReadPair：删除同一数据的冗余写后读路径。它避免在 VF 边界制造无用本地内存往返。该 pass 在 RegBase 向量化尾部运行。

3.2 A5 HIVM 的差异

  1. InsertCVTightCoupledBuffer：为 A5 Cube/Vector 通信显式建立 tightly-coupled buffer。它让两类核心通过受控的 L1/UB/TCB 路径交换数据。普通非 Triton A5 用它替代 A3 的部分 legacy load/store 插入。
  2. InsertL12UBForDebug：为 A5 调试观察插入 L1 到 UB 的搬运。它使原本只在 Cube 侧或 L1 中的数据能被 Vector 侧读取。A3 对应位置使用 InsertNZ2NDForDebug。
  3. InferVFMode：推导每个向量函数采用 SIMD、SIMT 还是混合模式。结论影响后续 AVE 或 Triton lowering 路径。它也为内存与核类型分析提供附加信息。
  4. PlanMemoryRegBase(GLOBAL/LOCAL)：执行 RegBase 专用的全局和局部内存规划。除生命周期和地址复用外，它还考虑 VF 可达性、动态 SIMT VF 大小和 TCB 复用限制。它是 A5 UB/L1 容量与地址正确性的核心 pass。
  5. DelayedCrossCoreGSS：在局部地址规划完成后重新求解跨核同步。第二阶段能看到最终地址复用和多缓冲槽位，因此比一次性求解更准确。第一阶段生成的 anchor/backup 信息用于连接拆核前后的依赖。
  6. OutlineAllocInVF、OutlineCopyInVF、BindBuffer：把 VF 内的 alloc 和入口 copy 移到调用者，并绑定实际 buffer。这样 VF 本身更接近纯计算函数。它也让 memscope 与 PlanMemory 能从调用侧统一观察内存。
  7. PreMarkStrideAlign：在正式 MarkStrideAlign 前预先识别需要 stride 对齐的候选。它利用 A5 RegBase 的访问模式提前传播约束。随后 EnableStrideAlign 才真正修改布局和签名。
  8. VFOperandSubstitution（条件）：用等价且更适合复用的值替换 VF 操作数。它可减少额外 buffer 或改善内存规划。只有对应选项开启时执行。
  9. PeelLoopsContainingTranspose、NormalizeVector、ArithVectorMaskAnalysis：剥离包含 transpose 的循环迭代，规范化 vector IR，并分析算术生成的 mask。它们为 AVE lowering 准备规则化向量操作。Direct HIVM lowering 模式会跳过该组。

3.3 A5 HIVMAVE 与 LLVM 前的 Lowering

  1. VectorToHIVMAVE：把 MLIR Vector 操作转换为 HIVMAVE 指令级操作。它根据目标和布局选择 AVE 可执行的表达。该 pass 是 A5 向量后端的主要入口。
  2. ArithToHIVMAVE：把仍与向量执行相关的算术转换为 HIVMAVE。标量控制算术若无需 AVE 会留给标准 lowering。它补齐 VectorToHIVMAVE 未覆盖的计算。
  3. I1opSoftImpl、I1ToI16Conversion：用软件序列实现硬件不直接支持的 i1 操作，并在需要时把谓词表示扩展为 i16。它们保证布尔/掩码语义能落到 AVE 指令。改写会尽量保留向量布局信息。
  4. ProcessVsstb、CombineAVEOPs、AveLoopOptimize：处理特殊 store，合并可组合的 AVE 操作，并优化 AVE 循环。该组减少指令数量和循环控制开销。合并只在数据依赖和布局允许时进行。
  5. LegalizeOptHIVMAVE、OptimizeReductionLoop、ProcessMembar：合法化优化后产生的 AVE 形态，专门优化归约循环，并整理 memory barrier。它们确保性能改写后仍满足硬件约束。Membar 处理负责保持正确的访存顺序。
  6. SIMTGridBlockPartition、SIMTLoopNestsScheduling（SIMT 条件）：把 SIMT grid 划分到物理 block，并调度嵌套循环。它们用于 A5 上的 SIMT VF 路径。纯 SIMD kernel 通常不会产生有效改写。
  7. PLTToPGE、PLTToPLTM：把程序级线程/循环表示逐步降低为更接近执行引擎的 PGE/PLTM 形式。它们明确线程、循环和谓词执行关系。后续布局分析基于该低层结构工作。
  8. LegalizeLoopIterArgs、AnalyzeVectorLayout：合法化循环迭代参数并求解每个向量值的布局。布局分析决定 lane、重复和数据分布方式。无法求解的布局会在这里尽早报错。
  9. AVENormalizeOps、RemoveVectorLayoutAttr：统一 AVE 操作形态，并在布局信息被编码进操作后移除临时属性。这样后续转换不再依赖分析期标记。当前分支的修复也集中在 Normalize 覆盖范围上。
  10. AnnotationLowering、AllocToAlloca、ConvertHIVMToStandard、ConvertHIVMAVEToStandard：降低注解和分配，并把 HIVM/HIVMAVE 的非指令部分转成标准 dialect。它们清除中高层 compiler-only 操作。转换选项会保留后续 intrinsic lowering 仍需识别的内容。
  11. ExpandStridedMetadata、HIVMAVEToAVEIntrin、HoistVstas：展开 stride metadata，把 AVE 操作转换为后端 intrinsic，并提升可移动的 vstas。此后向量计算基本表示为后端可识别调用。Hoist 用于减少循环内重复设置。
  12. AscendDPXToHIVMRegbaseIntrin、DecomposeFRem、SCFToCF、LowerAffine、ArithExpandOps：降低 DPX 指令，拆解浮点余数，并把结构化控制流、Affine 和复杂算术变成更基础形式。它们为 LLVM conversion 清除非法 dialect。部分 DPX 优化只在相关选项开启时运行。
  13. ConvertControlFlowToLLVM、ArithToLLVM、FixCallUnknownLoc：把控制流和算术转换到 LLVM dialect，并修复 call 的调试位置。结果可以交给 LLVM IR 翻译和 CCEC 后端。该组是 A5 in-tree lowering 的终点之一。

4. 条件分支与非默认 Pass

  1. TorchBackendToNamedOpBackendPipeline：仅在 Torch 编译开启时运行，把 Torch backend contract 转换为具名计算操作。它发生在 HFusion 前。本文没有展开其内部每个 Torch pass。
  2. AutoBlockifyParallelLoop：仅 Triton 且开启 auto-blockify 时，把超出物理核数的逻辑 block 包装成循环。它实现一个物理核顺序执行多个逻辑 block。核类型必须先由 InferFuncCoreType 推导。
  3. SIMTVFSubTiling、MaterializeSimtVFMemScope、HIVMToTritonGPU：用于 SIMD+SIMT 混合编译中拆出的 SIMT VF。它们细分 VF、落实内存空间并转到 TritonGPU。该旁路不属于普通纯 HIR A3/A5 主线。
  4. AutoScope、LegalizeBoolForSimtVF、InsertMemSemanticForSimtVF、OutlineScope：识别 SIMT 区域、合法化其布尔语义、补充内存语义并 outline 成独立 scope。它们在混合编译拆 module 前运行。作用是明确 SIMD 与 SIMT 边界。
  5. InsertAllocBasePlaceholder、InferSimtVFMemEffect、InferSimtVFMemScopeHint、SplitSimtModule：建立 SIMT 分配占位，推导内存副作用和 memscope hint，再拆出独立模块。主模块保留 SIMD/Cube 路径。拆出的模块进入 Triton lowering。
  6. TritonRemap、SCCP、AdaptGPUKernel：Triton 路径调整 program/block 映射，传播稀疏条件常量，并适配 GPU kernel ABI。它们服务 SIMT 或 Triton-only 编译。普通 HFusion/HIVM 主线不会运行。
  7. CreatePreload、PartitionAndBindSubBlock、VFFusion、AutoVectorizeV2 等虽然位于主 pipeline 中，但是否产生改写由选项和 IR 共同决定。HTML 展示时建议用"默认 / 条件 / 旁路"标签区分。不要仅依据 pass 被注册就判断它一定执行或一定改变 IR。

5. 转 HTML 的建议字段

每个 pass 建议转换成一个对象：order、name、stage、target、condition、summary、input_ir、output_ir。顺序表中的重复 pass 应保留独立 order，但 summary 可通过 pass 名称引用同一说明。A3/A5 共用项可标记 target: [A3, A5]，差异项分别标记 target: [A3] 或 target: [A5]。
