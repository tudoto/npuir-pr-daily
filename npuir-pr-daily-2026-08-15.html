#2651
[AscendNPU IR]: fix: apply padding b64
 愚岩 15:07

修复

修复 load_gm_to_ubuf_2d_int64_t 模板库 padding 处理导致的精度误差（median 结果错误）。根因：2D 场景下 size_aligned 错误使用 strides[0]（=16）而非 CEIL_FACTOR(size, num_per_block)（=12），导致 align_pad 被算成 7 而非 3；进而 vl_val（uint32_t）计算 4−7 发生无符号下溢变成 0xFFFFFFFD，使 mask 失效、有效数据被 pad_value 覆盖。修复后 padding 计算正确，精度恢复正常。
#2666
[AscendNPU IR][HFusion] Promote i1 reduce_with_index value to i32 in regbase normalize
 Jiangjiji 14:19

修复

修复 FlagGems test_bucket_sort_topk 精度失败问题。根因：i1（bool）类型的 reduce_with_index value operand 缺乏向量化 lowering，被 GenericUnroller 标量化为逐 bit GEP 寻址，硬件无法按 bit 寻址导致读出垃圾值，argmax 结果错误。修复方案：在 regbase normalize 阶段将 i1 value 提升为 i32（与已有 index 侧 normalize 对齐），从 IR lowering 层根治，Triton 侧无需改动。
#2248
[HFusion] Fix dissolvePivot self-conflict consistency check
 ykyyky 01:29

修复

修复 AutoVectorize V2 中 dissolvePivot 自冲突一致性检查的误报致命错误。当同一可融合算子同时是 barrier 的上游和下游时产生自冲突（a == b），两侧 map 查找解析到同一 DenseSet，两次 erase 返回值不同（1 vs 0）导致一致性检查误报并中止。修复方案：在 PlanContext.cpp 中用 a != b 守卫对称 erase 比较，自冲突时只 erase 一次，避免误报。
